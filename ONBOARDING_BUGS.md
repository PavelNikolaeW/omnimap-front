# Баги в системе Onboarding

Найдены критические баги в новой системе onboarding для пользователей. Необходимо исправить перед релизом.

---

## 🐛 БАГ #1: Блоки домашней страницы не отображаются при первом входе

**Приоритет:** 🔴 HIGH
**Метки:** `bug`, `onboarding`, `ux`, `critical`

### Описание
После регистрации нового пользователя и прохождения приветственного окна блоки домашней страницы не отображаются. Экран остается пустым, хотя в логах видно, что блоки успешно созданы.

### Шаги воспроизведения
1. Перейти на http://omnimap.cloud.ru/
2. Зарегистрировать нового пользователя
3. Нажать "Начать обзор" в приветственном окне
4. Наблюдать пустой экран

### Ожидаемое поведение
После инициализации должны отображаться блоки домашней страницы:
- Inbox
- Focus
- Projects
- Spaces
- Areas (с 8 подблоками)
- Archive

### Фактическое поведение
- Экран остается пустым
- Блоки появляются только после перезагрузки страницы (F5)
- В консоли видны успешные логи создания

### Логи консоли
```
[16:03:48] HomePageInitializer: Generated 14 blocks
[16:03:48] Dispatching event ShowBlocks
[16:03:48] HomePageInitializer: Onboarding completed successfully
[16:03:48] Dispatching event ShowOnboardingWelcome
```

### Возможная причина
Событие `ShowOnboardingWelcome` диспатчится после `ShowBlocks`, что может блокировать или прерывать отрисовку блоков. Возможна проблема в последовательности событий или в обработчике `ShowOnboardingWelcome`.

### Файлы для проверки
- `src/js/onboarding/onboardingManager.js` - обработчик события ShowOnboardingWelcome
- `src/js/onboarding/homePageInitializer.js` - инициализация домашней страницы
- `src/js/painter/painter.js` - рендеринг блоков
- `src/js/stateLocal/localStateManager.js` - управление состоянием блоков

### Предложенное решение
1. Проверить, что `ShowOnboardingWelcome` не блокирует основной контент
2. Убедиться, что Painter вызывается после диспатча `ShowBlocks`
3. Возможно нужно отложить показ приветственного окна до завершения рендеринга блоков
4. Добавить явный вызов перерисовки после закрытия приветственного окна

### Критерии приемки
- [ ] Блоки домашней страницы отображаются сразу после регистрации
- [ ] Приветственное окно не блокирует рендеринг
- [ ] Не требуется перезагрузка страницы для отображения блоков
- [ ] Добавлены E2E тесты для проверки onboarding flow

## 🐛 БАГ #2: Ошибка при создании блока на заполненной домашней странице

**Приоритет:** 🟡 MEDIUM
**Метки:** `bug`, `onboarding`, `layout-editor`, `ux`

### Описание
При попытке создать новый блок на автоматически заполненной домашней странице пользователь получает ошибку "Нет свободного места в сетке", но сами блоки не видны на экране. Это создает путаницу.

### Шаги воспроизведения
1. Зарегистрировать нового пользователя
2. Дождаться автоматической инициализации домашней страницы (или перезагрузить страницу)
3. Нажать `n` для создания нового блока
4. Ввести название и нажать OK

### Ожидаемое поведение
Один из вариантов:
- Блок создается в первой свободной ячейке grid
- ИЛИ отображается понятное сообщение с инструкцией как расширить сетку
- ИЛИ автоматически расширяется сетка для нового блока

### Фактическое поведение
- Консоль: `[WARNING] No free space in layoutCells grid`
- Всплывает сообщение: "Нет свободного места в сетке. Расширьте сетку в редакторе раскладки."
- Блоки домашней страницы не отображаются (связано с багом #1)
- Событие `ShowError` диспатчится

### Логи консоли
```
[16:11:45] Dispatching event CreateBlock
[16:11:45] [WARNING] No free space in layoutCells grid
[16:11:45] Dispatching event ShowError
```

### Возможная причина
1. Домашняя страница инициализируется с grid 4x12, который полностью заполнен
2. Логика создания блока не предусматривает автоматическое расширение grid
3. Пользователь не знает, как расширить сетку (hotkey `l+e` не очевиден)

### Файлы для проверки
- `src/js/controller/layoutEditor/layoutEditor.js` - редактор раскладки
- `src/js/painter/gridLayoutCalculator.js` - расчет свободного места
- `src/js/stateLocal/localStateManager.js` - метод createBlock
- `src/js/onboarding/homePageInitializer.js` - начальная конфигурация grid

### Предложенное решение

**Вариант 1 (рекомендуемый):**
При создании блока на заполненной home page:
1. Автоматически расширить grid на 1 строку
2. Разместить новый блок в новой строке
3. Показать hint о редакторе раскладки (один раз)

**Вариант 2:**
1. Оставить текущую домашнюю страницу с запасом (например, grid 5x12 вместо 4x12)
2. Резервировать последнюю строку для пользовательских блоков

**Вариант 3:**
1. Улучшить сообщение об ошибке: добавить кнопку "Открыть редактор раскладки"
2. При клике открывать редактор раскладки (hotkey `l+e`)
3. Показать hint о том, как добавить строки/колонки

### Критерии приемки
- [ ] Пользователь может создать блок на домашней странице без ошибок
- [ ] Либо grid расширяется автоматически, либо есть понятная инструкция
- [ ] Сообщение об ошибке содержит actionable решение
- [ ] Добавлены unit тесты для логики расширения grid
- [ ] Обновлена документация onboarding
